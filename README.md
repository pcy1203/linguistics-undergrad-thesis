# 한국어 의문문 해석 실험 (ver 2)

**ver 2 변경점**: 문항 36개를 한 블록으로 진행하고(`public/data/experiment.csv` 하나), 답변 3개를 **한 번에 하나씩** 보여 줍니다.
점수를 고르면 0.4초 뒤 다음 답변으로 넘어가고, 잘못 누른 경우에만 ‹ 버튼으로 돌아가 고칠 수 있습니다.

React(Vite) 정적 사이트 + 구글 시트(Apps Script) 로그 수집.

- 참여자마다 **A–F 집단 중 하나**가 배정됩니다. 서버가 완료 인원이 가장 적은 집단을 골라 주기 때문에 집단 크기가 고르게 맞춰집니다.
- 실험 1·2 각각 **24문항의 제시 순서**와 **문항마다 답변 순서**를 무작위로 섞습니다.
- CSV는 사이트가 열릴 때마다 새로 불러오므로, **CSV만 고치면 코드 수정 없이 반영**됩니다.

---

## 1. 로그용 구글 시트 만들기 (5분)

1. 구글 드라이브에서 **새 스프레드시트**를 만듭니다. (이름 예: `의문문 실험 로그`)
2. 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
3. 기본 `Code.gs` 내용을 지우고 이 저장소의 [`apps-script/Code.gs`](apps-script/Code.gs) 내용을 붙여 넣고 저장합니다.
4. 오른쪽 위 **배포 → 새 배포**를 누릅니다.
   - 유형 선택(톱니바퀴) → **웹 앱**
   - 실행 계정: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자** (서울대 계정으로 만들 때 "서울대학교 내 모든 사용자"를 고르면 외부 참여자의 기록이 저장되지 않습니다)
5. **배포**를 누르고 권한을 허용하면 `https://script.google.com/macros/s/…/exec` 주소가 나옵니다. 이 주소를 복사해 둡니다.

> `Code.gs`를 고친 뒤에는 **배포 → 배포 관리 → 수정(연필) → 버전: 새 버전**으로 다시 배포해야 반영됩니다. URL은 그대로 유지됩니다.

## 2. 사이트 배포하기 (Vercel 기준, 무료)

1. 이 폴더를 GitHub 저장소에 올립니다.
2. [vercel.com](https://vercel.com)에서 GitHub로 로그인한 뒤 **Add New → Project**에서 저장소를 고릅니다.
3. Framework는 자동으로 **Vite**가 잡힙니다. **Environment Variables**에 아래 값을 넣습니다.

   | 이름 | 값 |
   |---|---|
   | `VITE_LOG_ENDPOINT` | 1단계에서 복사한 `…/exec` 주소 |

   (이 저장소에는 기본 주소가 `src/config.ts`에 이미 들어 있어, 환경변수를 비워 두면 그 주소를 씁니다.)

4. **Deploy**를 누르면 1분 안에 `https://프로젝트이름.vercel.app` 주소가 생깁니다.

Netlify, GitHub Pages, Cloudflare Pages도 똑같이 동작합니다. 빌드 명령은 `npm run build`, 출력 폴더는 `dist`입니다.

## 3. CSV 수정하기

문항 파일은 `public/data/experiment.csv` 하나입니다.

- GitHub에서 CSV를 고치고 저장(commit)하면 Vercel이 **자동으로 다시 배포**합니다(약 1분).
- 배포 전에 CSV를 자동으로 점검합니다. 집단 누락, 빈 의문문, 답변 부족, item 번호 중복이 있으면 **배포가 실패하고 이전 버전이 그대로 유지**됩니다. 실패 이유는 Vercel의 빌드 로그에 한국어로 나옵니다.
- 엑셀에서 저장할 때는 **CSV UTF-8(쉼표로 분리)** 형식을 고르세요.

**CSV 규칙**

| 열 | 설명 |
|---|---|
| `group` | A–F |
| `item`, `trialType`, `condition`, `wh-type` | 그대로 로그에 기록됩니다 |
| `stimuli` | 화면에 보이는 의문문 |
| 이름에 `response`가 들어간 열 | 모두 답변으로 제시됩니다. 열을 늘리거나 줄여도 코드는 그대로입니다 |

- 줄바꿈은 어절(띄어쓰기) 단위로 자동으로 됩니다. 원하는 위치에서 직접 줄을 바꾸려면 문장 안에 `|`를 넣으세요. 예: `철수는 예지가 | 누구를 만났는지 말했니?`
- 집단마다 문항 수가 같아야 합니다(현재 36개).

### (선택) 배포 없이 구글 시트에서 바로 고치기

CSV를 구글 시트에 올려 두고 **파일 → 공유 → 웹에 게시 → 해당 시트 → CSV**로 게시한 주소를
`VITE_CSV_URL` 환경변수에 넣으면, 시트를 고치는 즉시 반영됩니다(구글 쪽 캐시로 최대 5분 지연). 이 방식은 배포 전 자동 점검이 적용되지 않습니다.

## 4. 테스트

| 주소 | 용도 |
|---|---|
| `…/?test=1` | 로그에 `is_test = TRUE`로 표시되고 집단 균형 계산에서 빠집니다. 본 실험 전 점검은 꼭 이걸로 하세요 |
| `…/?test=1&group=C` | C군 문항으로 고정 |
| `…/?reset=1` | 이 브라우저에 저장된 진행 기록을 지우고 처음부터 |

## 5. 쌓이는 데이터 (구글 시트 탭)

시간은 모두 ISO 형식의 **UTC**입니다(한국 시간 = UTC + 9시간). 탭은 처음 기록이 들어올 때 자동으로 생깁니다.

**참가자 번호**: 동의하는 순간 서버가 `P001`, `P002` … 순서대로 매깁니다. 테스트 접속(`?test=1`)은 `T001`부터 따로 셉니다.
서버에 연결되지 않으면 `X`로 시작하는 임시 번호(예: `XK7M2Q`)로 진행됩니다.
번호를 처음부터 다시 매기려면 Apps Script **프로젝트 설정 → 스크립트 속성**에서 `seq_P`(테스트는 `seq_T`)를 지우세요.

### 최종 제출 기록 (설문까지 마친 사람만)

| 탭 | 한 행 = | 내용 |
|---|---|---|
| **참여자** | 참여자 1명 | `completed_at`, `total_duration_s`, `resume_count`(끊겼다가 이어 한 횟수), 집단, 단계별 시각, 설문 |
| **제시 순서** | 참여자 1명 × 실험 | `t01`~`t24` 칸에 몇 번째로 몇 번 아이템을 받았는지 (`17 (NI-SS)`, `22 (filler)`) |
| **응답 결과** | 문항 1개 | 답변 종류별 점수와 최종 응답 시간(`…_rt_ms`), 문항 소요 시간, `resumed` |
| **응답 세부** | 답변 1개 | 제시 순서(`answer_position`), 점수, 응답 시간, 누른 횟수, 클릭 기록, ‹ 관련 기록, `resumed` (아래 표) |
| **추첨** | 전화번호 1건 | 날짜와 전화번호만 (응답과 연결되지 않도록 참여자 ID 없음) |

### 중간 기록 (완료 여부와 상관없이 모두)

| 탭 | 한 행 = | 내용 |
|---|---|---|
| **진행 현황** | 참여자 1명 | 참가자 번호, 집단, `status`(진행 중/완료), 마지막으로 푼 문항, 푼 문항 수, 시작·마지막 기록·완료 시각 |
| **중간 기록** | 답변 1개 | 문항이 끝날 때마다 바로 기록. 열 구성은 `응답 세부`와 같고 `record_key`, `logged_at`이 추가됨 |

- 분석에는 **최종 제출 기록**을 쓰세요. 중간에 그만둔 사람은 `진행 현황`에서 `status = 진행 중`으로 남아 있고, 그때까지의 응답은 `중간 기록`에만 있습니다.
- `resumed = TRUE`인 문항은 그 문항을 푸는 도중에 끊겼다가 다시 시작한 것이라 **응답 시간 해석에 주의**하세요.
**응답 세부의 시간·이동 기록**

| 열 | 뜻 |
|---|---|
| `shown_at_ms` | 이 답변이 처음 나타난 시점 (문항이 나타난 순간 = 0) |
| `rt_first_ms`, `rt_final_ms` | **이 답변이 처음 나타난 순간부터** 점수를 처음 / 마지막으로 누른 순간까지 |
| `rt_final_from_trial_ms` | 문항이 나타난 순간부터 이 답변의 점수를 마지막으로 누른 순간까지 |
| `n_views` | 이 답변이 화면에 나타난 횟수 (2 이상이면 ‹ 로 돌아와 다시 본 것) |
| `changed_on_revisit` | ‹ 로 돌아와서 점수를 바꿨는지 |
| `n_back` | 그 문항에서 ‹ 버튼을 누른 횟수 (응답 결과 시트에도 있음) |
| `click_log` | 누른 기록 전체 (`문항 기준 ms→점수`) |

- 각 문항에서 **처음 제시된 답(`answer_position = 1`)**은 다른 답을 보기 전의 독립 판단이라, "비교 효과" 반론에 대한 강건성 분석에 쓸 수 있습니다.

## 5-1. 끊겼을 때 이어서 하기

- 진행 상황(문항 순서·답변 순서·지금까지의 응답)은 **문항이 끝날 때마다 참여자의 브라우저에 저장**됩니다.
- 새로고침, 탭 닫기, 앱 전환, 배터리 방전 뒤에 **같은 기기·같은 브라우저**로 링크를 다시 열면 "진행하던 실험이 있습니다." 화면이 나오고, 멈춘 문항부터 이어집니다. 참여자가 번호를 기억할 필요는 없습니다.
- 풀던 문항은 처음부터 다시 풀고, 그 문항에 `resumed` 표시가 남습니다.
- 마지막 저장 후 **24시간**이 지나면 이어서 하기는 사라지고 새 참여자로 시작합니다.
- 다른 기기로 옮기거나 브라우저 데이터를 지우면 이어서 할 수 없습니다.
- 제출을 마친 브라우저로 다시 열면 완료 화면과 참여 번호가 보입니다(중복 참여 방지). 같은 기기로 여러 번 테스트하려면 주소 끝에 `?reset=1`을 붙이세요.

## 6. 로컬에서 실행

```bash
npm install
npm run dev        # http://localhost:5173  (VITE_LOG_ENDPOINT가 없으면 로그를 브라우저 콘솔에 출력)
npm run check:csv  # CSV 점검만
npm run build      # 배포용 빌드 → dist/
```

로컬에서도 구글 시트로 보내 보려면 `.env.example`을 `.env.local`로 복사한 뒤 주소를 넣으세요.

```
src/lib/log.ts        응답 시간 기록, 시트 행 만들기, 전송

scripts/check-csv.mjs 배포 전 CSV 점검
```
